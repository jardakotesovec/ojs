- **Area:** 8. System & communications
- **Placement:** lib/pkp (rows 2–3 absorb OJS-side specs under `playwright/tests/scenarios/` — the seeded decision chains are OJS-specific; they stay OJS-side on refit)
- **Budget:** 8 tests
- **Absorbs:** lib/pkp/playwright/tests/journal-scenario.spec.js (BOTH tests → row 1; sole owner — `site-administration` released its claim, and its rows now exercise the admin-wizard UI instead); playwright/tests/scenarios/submission-stage.spec.js (2 tests → row 2); playwright/tests/scenarios/submission-in-round-2.spec.js (row 3); lib/pkp/playwright/tests/scenario-default-file.spec.js (rows 4–5); lib/pkp/playwright/tests/scenario-decision-comments.spec.js (2 tests → row 6); lib/pkp/playwright/tests/mailpit.spec.js — clearAll + Mail::fake tests only (row 7; relocated wave 12 to lib/pkp/playwright/tests/serial/mailpit-harness.spec.js per principles 8–9; the password-reset test is absorbed-with-rework by `password-flows`); lib/pkp/playwright/tests/reduced-motion.spec.js (3 tests → row 8)
- **Scenario needs:** the scenario endpoints, Mailpit fixture, and reduced-motion config wiring are themselves the system under test. No GAP. This plan deliberately guards the seeding contract only — feature behavior on top of seeded state belongs to the feature plans (see `editorial-dashboards`, which explicitly disclaims row 2's specs). **Wave-1 work item:** scenario schema validation is currently dead code — `opis/json-schema` is not installed, so `validateAgainstSchema` silently degrades to a no-op; wave 1 must install/enforce it and sync `context.json` with the Processor whitelists (e.g. `enableAnnouncements`), otherwise invalid specs seed garbage instead of failing fast.
- **Round 2 / out of scope:**
  - Scenario-endpoint negative paths (schema-invalid spec → 4xx with useful message, TestModeGate rejection without key/env).
  - `aggregate-scenario-timing.js` runtime-budget regression checks (process-level, not a Playwright test).
  - Auth storage-state staleness probe self-test — exercised implicitly by `login-as` flows.
  - Bootstrap idempotency / `test:e2e:reset` cold-boot verification (setup-project concern).
  - Scenario client fixture (`support/scenarios.js` SEAM stub) — flagged TODO; rows keep POSTing via `pkpApi` until it lands.
