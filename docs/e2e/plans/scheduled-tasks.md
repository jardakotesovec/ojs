# Scheduled tasks

- **Area:** 8. System & communications
- **Placement:** lib/pkp
- **Budget:** 4 tests
- **Absorbs:** none
- **Execution:** DEDICATED SERIAL PLAYWRIGHT PROJECT (principle 9) — a serial spec file inside the parallel project is NOT enough. `scheduler.php test --name=ReviewReminder` scans ALL review assignments globally: if any parallel worker holds an overdue assignment mid-test, the trigger would email its reviewer and set `dateReminded` on it, corrupting that sibling test. The same applies to `EditorialReminders`. These rows therefore run in their own serial Playwright project with no parallel siblings; `withoutOverlapping` additionally mutexes the named events. Assertions remain scoped to throwaway recipient + tag regardless, because the task still walks whatever assignments exist in the DB.
- **Scenario needs:** submission scenario reviewer fields `status` + `responseDueDate`/`reviewDueDate` (exist in `schema/submission.json`); throwaway reviewer/editor users via journal scenario `users[]` on a scratch journal for ALL rows — never shared seeded users (phudson/jjanssen/minoue), whose inboxes and assignments collect traffic from the rest of the suite. **Trigger mechanism (verified):** no test-only HTTP endpoint exists; the built-in `[schedule] task_runner = On` fires non-deterministically (60 s interval, tasks on daily/monthly crontabs), so tests shell out `APPLICATION_ENV=test php lib/pkp/tools/scheduler.php test --name="PKP\task\ReviewReminder"` (resp. `EditorialReminders`) — the `test --name` path runs one named CallbackEvent synchronously and non-interactively (tools/scheduler.php; tasks registered by name in classes/scheduler/Scheduler.php). Reminder mailables are dispatched as queued jobs, drained deterministically with `php lib/pkp/tools/jobs.php run`. **Reminder thresholds (rows 1–3, conditional):** thresholds are context settings and publicknowledge is read-only at test time. Resolve via the wave-1 bootstrap enrichment "review response/submit deadlines + reminders configured" on publicknowledge first — rows 1–3 then seed their submissions on publicknowledge with the throwaway reviewers. ONLY if that enrichment is declined, build the two-scalar context passthrough (`numDaysBefore/AfterReviewResponseReminderDue` + `numDaysBefore/AfterReviewSubmitReminderDue`) so the scratch journal carries the thresholds itself; until then it stays conditional and unbuilt (`context.json` has `additionalProperties: false`, so it cannot be seeded today — record as `GAP:` only if the enrichment falls through).
- **Round 2 / out of scope:**
  - SubscriptionExpiryReminder (round-2 backlog), OpenAccessNotification, UsageStatsLoader (stats pipeline is round 2), RemoveExpiredInvitations/RemoveFailedJobs housekeeping tasks.
  - DepositDois task — deposit semantics owned by `crossref-deposit`/`doi-management`; never live in tests.
  - StatisticsReport monthly editorial-report email.
  - Built-in end-of-request task-runner timing behavior (inherently nondeterministic; the runner being On is exercised passively by the whole suite).
