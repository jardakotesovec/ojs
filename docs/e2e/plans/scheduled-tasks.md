# Scheduled tasks

- **Area:** 8. System & communications
- **Placement:** lib/pkp
- **Budget:** 4 tests
- **Absorbs:** none
- **Execution:** DEDICATED SERIAL PLAYWRIGHT PROJECT (principle 9) — a serial spec file inside the parallel project is NOT enough. `scheduler.php test --name=ReviewReminder` scans ALL review assignments globally: if any parallel worker holds an overdue assignment mid-test, the trigger would email its reviewer and set `dateReminded` on it, corrupting that sibling test. The same applies to `EditorialReminders` (whose digests to SHARED editors additionally interpolate the tag-marked titles of every outstanding submission — breaking sibling `expectNone` scopes). These rows therefore run in their own serial Playwright project with no parallel siblings; `withoutOverlapping` additionally mutexes the named events. Assertions remain scoped to throwaway recipient + tag regardless, because the task still walks whatever assignments exist in the DB. **Verified hazard (wave 12) — the serial-isolation requirement is two-way:** if ANY scenario-seeding request completes anywhere on the shared DB between the scheduler dispatch and the CLI jobs drain, the end-of-request JobRunner (`PKPQueueProvider.php:116-150`, `[queues] job_runner=On`) pops the queued reminder job inside that request's process, where the scenario controller's `Mail::fake()` (`PKPSubmissionScenarioController.php:84`) is active — the job's side effects commit (`dateReminded` stamped) but the message is swallowed before SMTP. Observed live (row 3, first verification run, sibling agents seeding concurrently); impossible in the canonical lifecycle where the serial project runs after the parallel suite finishes. Do not run these rows while parallel agents are seeding.
- **Scenario needs:** submission scenario reviewer fields `status` + `responseDueDate`/`reviewDueDate` (exist in `schema/submission.json`); throwaway reviewer/editor users via journal scenario `users[]` on a scratch journal for ALL rows — never shared seeded users (phudson/jjanssen/minoue), whose inboxes and assignments collect traffic from the rest of the suite. **Trigger mechanism (verified):** no test-only HTTP endpoint exists; the built-in `[schedule] task_runner = On` fires non-deterministically (60 s interval, tasks on daily/monthly crontabs), so tests shell out `APPLICATION_ENV=test php lib/pkp/tools/scheduler.php test --name="PKP\task\ReviewReminder"` (resp. `EditorialReminders`) — the `test --name` path runs one named CallbackEvent synchronously and non-interactively (tools/scheduler.php; tasks registered by name in classes/scheduler/Scheduler.php). Reminder mailables are dispatched as queued jobs, drained deterministically with `php lib/pkp/tools/jobs.php run`. **Reminder thresholds (rows 1–3, RESOLVED 2026-06-11):** the wave-1 bootstrap enrichment set deadlines + all four reminder thresholds (2 days before/after, response + submit) on publicknowledge, so rows 1–3 seed their submissions there with throwaway reviewers. Additionally, the wave-1 schema sync made `numWeeksPerResponse`/`numWeeksPerReview` and all four `numDaysBefore/After…ReminderDue` scalars first-class context-scenario passthroughs, so a scratch journal can carry its own thresholds if a row ever needs different values.
- **Round 2 / out of scope:**
  - SubscriptionExpiryReminder (round-2 backlog), OpenAccessNotification, UsageStatsLoader (stats pipeline is round 2), RemoveExpiredInvitations/RemoveFailedJobs housekeeping tasks.
  - DepositDois task — deposit semantics owned by `crossref-deposit`/`doi-management`; never live in tests.
  - StatisticsReport monthly editorial-report email.
  - Built-in end-of-request task-runner timing behavior (inherently nondeterministic; the runner being On is exercised passively by the whole suite).
