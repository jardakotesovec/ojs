# Review forms

- **Area:** 2. Editorial workflow
- **Placement:** lib/pkp
- **Budget:** 6 tests
- **Absorbs:** none
- **Scenario needs:** journal scenario with users (existing — review forms are journal-level, so every row runs on a scratch journal; publicknowledge stays untouched); submission scenario with `journal` override (existing). Verified in code: review form *attachment* is per-assignment (`ReviewerForm`/`EditReviewForm` carry `reviewFormId`), but the forms themselves are journal settings (Settings > Workflow > Review > Review Forms legacy grid), so even attachment rows need a scratch journal with a form in it.
  - ~~`GAP: context scenario reviewForms[]`~~ **LANDED (wave 1)** — context scenario accepts `reviewForms: [{title, description?, elements: [{type, question, required?, includedInReview?, options?}]}]` (`ReviewFormProcessor`, grid parity: insert inactive → resequence → activate; element types smalltextfield/textfield/textarea/checkboxes/radiobuttons/dropdown; options required for multiple-response types). Response echoes `reviewForms: [{id, title, elementIds}]`, which is what the specs use to address response controls. Original adjudication: rows 2–6 all need a pre-existing form; creating one through the legacy grid UI per test is slow and duplicates row 1's coverage. Multiple rows ⇒ justified Processor extension per PRINCIPLES §3; parity entry in `docs/scenario-processor-audit.md`.
  - ~~`GAP: submission scenario reviewRounds[].reviewers[].reviewFormId`~~ **LANDED (wave 1, shape changed)** — per-reviewer `reviewForm: "<title>"` (exact-title match against the context's *active* forms, mirroring the Add Reviewer dropdown; `ReviewRoundProcessor::resolveReviewFormId` stamps the validated `reviewFormId` into createParams). Title-keyed rather than id-keyed so specs don't have to thread DB ids between the two scenario calls. Original adjudication: rows 4–6 need the assignment to already carry the form without driving the Add Reviewer modal each time; same multi-row justification; parity entry in `docs/scenario-processor-audit.md`.
- **Round 2 / out of scope:**
  - Multilingual review-form element entry (covered in spirit by languages-locales plan).
  - Section-default review form (`Section::getReviewFormId` preselects in the Add Reviewer modal) — sections plan territory.
  - Review-form responses in exports/reports.
