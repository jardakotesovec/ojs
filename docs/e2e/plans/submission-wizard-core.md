# Submission wizard — core

- **Area:** 1. Submission intake
- **Placement:** lib/pkp
- **Budget:** 14 tests
- **Absorbs:** none (`playwright/tests/submission.spec.js` was a 0-test fixme stub — superseded by this plan; **deleted during implementation**, replaced by `lib/pkp/playwright/tests/submission-wizard-core.spec.js`)
- **Scenario needs:** journal scenario for scratch journals (existing); submission scenario with `submitted: true` (routing row). The originally planned `submitted: false` seeding for the wizard-step rows turned out **not wizard-resumable**: `SubmissionBuilderProcessor` creates submissions with `submissionProgress` already cleared (plus a `dateSubmitted`), so the wizard route shows the "Submission complete" screen for them (`PKPSubmissionHandler::index` routes on `submissionProgress`). Per charter principle 3 no Processor change was made — drafts are started through the Begin Submission form inside each test (~2s, itself wizard surface). If a future plan needs many seeded wizard drafts, extend the Processor with an explicit draft mode + parity-audit entry instead.
- **Round 2 / out of scope:**
  - Dropzone failure dictionary (file too big, invalid type, cancel upload) — config-driven, flake-prone.
  - beforeunload unsaved-changes prompt and disconnected-state banner (i18nDisconnected).
  - Custom guidance text configured through the settings UI (owned by `submission-settings` plan; row 8 here asserts only the shipped defaults render).
  - Journal "Submissions" about page content and checklist editing (owned by `submission-settings`).
  - Start-form per-section policy reveal (row 1): the seeded publicknowledge sections carry no `policy` (bootstrap `SectionProcessor` doesn't set one), and the OJS StartSubmission form only adds the `sectionDescription{id}` reveal for sections with a non-empty localized policy. Needs either a bootstrap-section policy (bootstrap change — post-wave-1 freeze) or a section `policy` passthrough in the journal scenario; deferred.

## Implementation notes (verified against the real UI)

- **Row 3 — no rename in the wizard.** The wizard's file Edit modal is `PKPSubmissionFileForm`, which holds only the `genreId` radio; file rename does not exist in the wizard UI (it's a workflow-stage feature). The rename sub-assertion was replaced by genre editing through that modal.
- **Row 4 — no subtitle in the wizard.** The wizard's Details form (`PKP\components\forms\publication\Details`) removes `prefix` and `subtitle`; the row covers title/abstract/keywords instead (keywords are requested on the enriched publicknowledge bootstrap).
- **Row 9 — group choice is constrained twice.** The Submit As radio only offers groups with submission-stage access (so `manager` never shows — the Journal manager group carries no stage assignments in `registry/userGroups.xml`), while `POST /submissions` only accepts manager- or author-role groups (editor/sectionEditor choices 400 with `api.submissions.400.invalidSubmitAs`; pkp/pkp-lib#10929 tracks the mismatch). The test uses Author + Translator (both ROLE_ID_AUTHOR, both stage 1) on a scratch journal.
- **Row 12 —** the denial surface is the `/user/authorizationDenied` redirect with `user.authorization.roleBasedAccessDenied` ("The current role does not have access to this operation.").
- Implementation also hardened shared support: `auth.js` fresh-login contexts and the spec's anonymous/scratch contexts pass an explicit empty `storageState` (under `@playwright/test`, `browser.newContext()` inherits the file-level user's storage state); `SubmissionWizardPage#gotoStep`/`expectStep` end-anchor the step-name match ("Review" otherwise resolves to the "Reviewer Suggestions" pill) and retry clicks swallowed by the steps-rail re-render.
