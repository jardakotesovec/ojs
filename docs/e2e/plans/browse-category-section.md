# Browse: categories & section policies

- **Area:** 4. Reader front end
- **Placement:** ojs
- **Budget:** 4 tests
- **Absorbs:** none
- **Scenario needs:** journal scenario (`categories` tree, `sections` with `editorRestricted`, `issues`); submission-published fixture. Section `policy` text is not a SectionProcessor field — seeded via the sections settings UI (one-off, keep). **Adjudicated verdict:** `publications[].categories` = **UI-FALLBACK**, no Processor extension — only row 1 truly needs "published article in category" state (the categories plan's row stops at assignment persistence, and the homepage category listing is round 2), below the multi-row bar of principle 3; row 1 reaches the state by driving the publication's category assignment through the workflow UI and republishing. Note: `catalog/category/{path}` resolves articles through the search index (`SubmissionSearchResult` filtered by categoryIds), so the same poll-until-indexed caveat as site-search applies (owned by row 1). **Implementation notes (wave 8, run-verified):** row 1 seeds the publication `published: false` (publish happens in the UI — equivalent to unpublish-and-republish, one round-trip cheaper); the workflow's Publication Settings panel has a REQUIRED Issue select that the queued seed leaves empty (the scenario stores the issue ref for the publish step only), so the test assigns issue placement in the same form save as the category. Single-locale scratch journals use locale-UNPREFIXED front-end URLs (the `/en/` form 302s back). The legacy sections grid needs the TARGET row's own `a.show_extras` expanded — clicking another row's toggle leaves the Edit action hidden. App-bug candidate (row 3): `catalogCategory.tpl:68` `{if empty($results)}` is dead code against the `LengthAwarePaginator` that `PKPCatalogHandler::category` (line 82) now assigns, so the `catalog.category.noItems` empty-state message can never render — the real empty state is a "0 Items" count plus an entry-less list.
- **Round 2 / out of scope:**
  - Category sort options (`getSortOption`) and ordering assertions.
  - Category cover images on browse pages.
  - Homepage category listing (`JournalContentOption::CATEGORY_LISTING` theme option).
  - Browse block plugin (disabled by default; long-tail).
  - Section policy editing UI itself (sections feature, area 6 — this plan only asserts the public render).
