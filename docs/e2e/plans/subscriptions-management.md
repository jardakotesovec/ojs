# Subscriptions management

- **Area:** 7. Plugins (key set)
- **Placement:** ojs
- **Budget:** 9 tests
- **Absorbs:** playwright/tests/subscription-config.spec.js (4 of its 5 tests — types create/delete, policies, publishingMode; the Payments-settings test is absorbed by the payments plan)
- **Scenario needs:** journal scenario (`users` incl. `reader` role, `publishingMode`, `issues` passthroughs — all existing). Every test runs on a scratch journal: publicknowledge stays open access and READ-ONLY. Subscription types/subscriptions in rows 1–7 are created through the legacy grids — the grids ARE the behavior under test. **`subscriptions[]` seeding — BUILT in wave 1** (`classes/testing/bootstrap/Processor/SubscriptionProcessor.php`, hung off `JournalScenarioController::afterContextCreated`; OJS-only, NOT in the shared scenario schema; parity entry in `docs/scenario-processor-audit.md`). Item shape: `{type: {name, duration?, cost?, currency?, format?, institutional?}, user?, institution?: {name, ipRanges}, status?: 'active'|'expired', dateStart?, dateEnd?}` — each item creates one TYPE plus one subscription row; `'expired'` seeds an ACTIVE-status row with a past `date_end`. Used here by rows 8–9, where the type/granted subscription is a precondition, not the grid behavior under test. **Implementation notes (wave 11):** (a) `/about/subscriptions` 302s to the journal index unless `paymentsEnabled && paymentManager->isConfigured()` (`pages/about/AboutHandler.php#40-45`) — row 8 configures ManualPayment via `PUT /api/v1/_payments` (REST seeding; the form UI is covered by the payments-plan test in subscription-config.spec.js; note the endpoint string-compares `paymentsEnabled === 'true'`). (b) The institutional subscription form carries NO inline institution-name/IP fields — it references an institution (`select[name=institutionId]`) managed at Settings → Institutions (`PKPInstitutionForm`: name + ipRanges), so row 7 creates the institution through that list panel and round-trips the IP range there. Shared POM: `playwright/pages/SubscriptionManagementPage.js`.
- **Round 2 / out of scope:**
  - Subscription expiry reminder scheduled task — round-2 backlog per inventory.
  - Online self-serve subscription purchase with payment gateway — payment gateway live flows are round 2; the request-side surface is covered by the payments plan.
  - Subscription notify-email checkbox on the subscription form (SubscriptionNotify mailable) — depends on policy contact fields; low traffic.
  - Bulk subscriber import / renewals at scale.
