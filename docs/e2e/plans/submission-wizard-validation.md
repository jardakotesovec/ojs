# Submission wizard — validation

- **Area:** 1. Submission intake
- **Placement:** lib/pkp
- **Budget:** 10 tests
- **Absorbs:** ABSORBED + DELETED (merged into `lib/pkp/playwright/tests/submission-wizard-validation.spec.js`): `wizard-validation.spec.js` (1 test → row 2), `wizard-copyright-notice.spec.js` (2 tests → row 3, EN + FR), `wizard-section-rules.spec.js` (2 tests → row 4). The merged spec carries 11 tests backing 9 implemented rows. `lib/pkp/playwright/tests/wizard-comments-become-discussion.spec.js` is NOT absorbed here: its seeded-comments test is owned by `plans/discussions.md` as Absorbs (rework); its wizard end-to-end test remains a fixme there, while row 7 below re-implements the wizard-typed-comments surface deterministically (autosave anchored via REST poll before Submit).
- **Scenario needs:** journal scenario with `copyrightNotice`, `sections` (incl. `editorRestricted`) and `contact` passthroughs (existing); submission scenario `submitted: false` wizard drafts (existing as of the draft-shape fix: `submissionProgress='start'`, no dateSubmitted, author assignment with `canChangeMetadata=true` mirroring PKPSubmissionController::add — without that flag the wizard rejects the author's autosaves with userCantEdit). Section inactivation/editor-restriction flips have no scenario passthrough — done via the sections settings grid inside the test (helper in the spec); one-off state, no GAP requested. Row 10 deliberately does NOT seed a draft: seeded submissions auto-attach a genre-resolved Article Text file, which would already satisfy the required-genre check the row violates — it drives the Start form + upload UI instead.
- **Round 2 / out of scope:**
  - Journal-without-privacy-statement variant (consent field absent) — needs a privacyStatement passthrough nobody else needs.
  - ORCID-required contributor validation (owned by `orcid` plan).
  - FR-locale validation rendering (owned by `submission-wizard-language` rows 2–3).
  - Require-mode metadata errors (owned by `submission-wizard-metadata` rows 5, 11).
  - Known flake: wizard-comments-become-discussion test 2 intermittently loses commentsForTheEditors after Submit (pre-existing, documented in scenario audit §3); tracked as a defect, not replanned here. Row 7's re-implementation sidesteps the suspected mechanism (the wizard queues autosaves on a 500ms runner while Review's `_validateOnly` polls `isAutosaving` on an independent 500ms timer — a queued-but-unsent autosave is invisible to it) by REST-polling the persisted draft before Submit.
