# Usage statistics

- **Area:** 7. Plugins (key set)
- **Placement:** lib/pkp
- **Budget:** 6 tests
- **Absorbs:** playwright/tests/article-statistics.spec.js (1 test; MOVED during the wave-11 refit to lib/pkp/playwright/tests/usage-statistics.spec.js — the stats handlers and Vue pages are shared, only the "Articles" locale override is OJS)
- **Scenario needs:** `submission-published` fixture (publicknowledge); journal scenario `users` passthrough for exact-count rows. **Minimal metrics seed — BUILT (wave 1, OJS-only):** the submission scenario accepts `metrics: {views?, downloads?, months?}` (`SubmissionScenarioController::schemaOverlayProperties()` → `classes/testing/bootstrap/Processor/MetricsProcessor.php`). It writes compiled `metrics_submission` rows at compile-step column parity: monthly buckets on the 1st of each month spread backwards from the current month (default `months: 3`), totals split evenly with the remainder credited to the most recent bucket; download rows reuse the publication's real galley/file ids when one exists (seed `galleys: [{label: 'PDF'}]` alongside for full parity). The scenario response echoes `metrics.rows: [{date, assocType: 'submission'|'submissionFile', metric}]` — tests derive date-range filters from that echo, never from the client clock. This serves rows 4–5's date-filter/report needs in full. Replaces the dropped Cypress `generateTestMetrics.php` shell-out (migration roadmap row #36).
- **Implementation findings (wave 11):**
  - **"All Dates" is unusable on freshly-seeded journals (app bug):** with no `dateStart`, `PKPStatsPublicationController::_processAllowedParams()` (lib/pkp, #802-810) substitutes the context's earliest `date_published`, while `dateEnd` defaults to *yesterday* (`PKPStatsPublicationService::getDefaultArgs()`, #292-293). On a journal whose earliest publication was published today (every scenario-seeded journal/DB), that yields `date BETWEEN today AND yesterday` → always-empty items/timeline despite existing metrics. Tests use explicit custom ranges instead; flagged for the app-changes ledger.
  - The current-month metrics bucket (1st of this month) is unreachable through the stats UI when a run happens ON the 1st (date validator caps `dateEnd` at yesterday). Rows 4–5 therefore assert on past-month buckets only — run-date safe.
  - On default scratch-journal user groups (`registry/userGroups.xml#18`), the `editor` group carries ROLE_ID_MANAGER — a scenario user with role `editor` counts under "Journal Manager", not "Section Editor" (row 3 expectations encode this).
  - OJS appends a JATS column to both the detail table (`pages/stats/StatsHandler.php::getTableColumns`) and the CSV; the JSON items omit `jatsViews`, so table body rows render 7 cells under 8 headers (cosmetic header/body mismatch; assertions use stable cell indices 1–2).
  - The client prepends parameter rows (date range / filters / search phrase) to the downloaded CSV before the API payload — the search-phrase row also contains the tag, so CSV assertions anchor on the title text.
- **Round 2 / out of scope:**
  - Usage-statistics pipeline (log processing/compilation), geo/institution stats, SUSHI/COUNTER R5 endpoint correctness — explicitly round-2 per inventory and PRINCIPLES.
  - Issues stats page (`/stats/issues`, OJS-only) and the legacy report generator variants (`/stats/reports`) — beyond the publications CSV row.
  - Reviewer-activity averages on the editorial page — derived numbers, unit territory.
