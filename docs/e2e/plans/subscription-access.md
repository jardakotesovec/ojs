# Subscription access

- **Area:** 7. Plugins (key set)
- **Placement:** ojs
- **Budget:** 6 tests
- **Absorbs:** playwright/tests/subscription-access.spec.js (2 tests)
- **Scenario needs:** journal scenario (`publishingMode`, `users` incl. throwaway readers via username+password, `issues` with `accessStatus` passthroughs — all existing); `submission-published` fixture with `journal`/`issue` overrides. PDF galley: rows 1–2 add it via the EditorialWorkflowPage POM (the add-galley flow doubles as coverage); rows 3–6 seed it via the `publications[].galleys[]` passthrough (wave-1 build) — either way it is a real publication galley, which the `restricted` gate signal needs (the JATS auto-link bypasses galley_link.tpl). All on scratch journals — publicknowledge stays open access, READ-ONLY. **`subscriptions[]` seeding — BUILT in wave 1** (`classes/testing/bootstrap/Processor/SubscriptionProcessor.php`, hung off `JournalScenarioController::afterContextCreated`; OJS-only, NOT in the shared scenario schema; parity entry in `docs/scenario-processor-audit.md`). Item shape: `{type: {name, duration?, cost?, currency?, format?, institutional?}, user?, institution?: {name, ipRanges}, status?: 'active'|'expired', dateStart?, dateEnd?}` — each item creates its own TYPE plus one subscription row; `'expired'` seeds an ACTIVE-status row with a past `date_end` (the lapsed state unreachable through the create form); default dates resolve PHP-side (no Node-vs-PHP clock skew). Used for expired/institutional/active-control *preconditions* (rows 3–5 here, subscriptions-management rows 8–9) — not the behavior under test. **Implementation note (wave 11):** row 3's redirect target `/about/subscriptions` itself 302s on to the journal index unless payments are configured (`AboutHandler::subscriptions#40-45`), so the test enables ManualPayment via `PUT /api/v1/_payments` while leaving `purchaseArticleFee` unset to stay on the no-fees redirect branch of `ArticleHandler::userCanViewGalley#672-677`.
- **Round 2 / out of scope:**
  - Purchase-to-unlock flows (article/issue purchase granting access after payment) — gateway side covered by the payments plan; completed-purchase access is round 2.
  - Membership-based access (`dateEndMembership`) — rare configuration.
  - `restrictOnlyPdf` partial gating variant.
  - Subscription expiry reminder task — round-2 backlog per inventory.
