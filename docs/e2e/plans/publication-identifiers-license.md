- **Budget:** 8 tests
- **Absorbs:** none
- **Scenario needs:** submission scenario `publications[].metadata` (copyrightHolder/copyrightYear/licenseUrl, title/abstract per locale) — exists; journal scenario `plugins: {urnpubidplugin: {enabled: true, settings}}` passthrough for the pub-id-gated Identifiers tab — exists (settings MUST include `enablePublicationURN: true` and `urnCheckNo: false` — see Implementation notes for the app bug that makes `urnCheckNo` mandatory). `enablePublisherId` is not a context-scenario field: one-off, toggled via the Workflow > Metadata settings UI on a scratch journal (row 5), so no GAP. ## Implementation notes (wave 6)

- **Runs:** green twice consecutively at `--workers=2` (8/8 passed; 37s and 72s wall — second run under sibling-agent load on the shared servers).
- **APP BUG (diagnosed, worked around — needs an app-changes.md ledger row):** enabling the URN plugin + `enablePublicationURN` *without* a stored `urnCheckNo` setting breaks the Identifiers form silently. `URNPubIdPlugin::addPublicationFormFields` passes `$this->getSetting($contextId, 'urnCheckNo')` (null when the row is absent) straight into `FieldTextUrn`'s typed `public bool $applyCheckNumber` (plugins/pubIds/urn/URNPubIdPlugin.php:348 → :387-392; assignment in lib/pkp/classes/components/forms/Field.php:78-86 → `TypeError: Cannot assign null to property ...FieldTextUrn::$applyCheckNumber of type bool`). `Hook::run` swallows the TypeError ("Plugin ... failed to handle the hook Form::config::before", lib/pkp/classes/plugins/Hook.php:162), so `_components/identifier` returns 200 with `fields: []` and the panel renders empty — while the Identifiers nav item still shows. Same hazard for the `FieldPubIdUrn` branch (URNPubIdPlugin.php:361) and presumably any seeded/partial-settings path; the real settings form always writes `urnCheckNo`, which is why the UI path masks it. Suggested fix: cast `(bool)` at URNPubIdPlugin.php:348. Suggested ledger wording: "URN plugin: unset urnCheckNo setting null-TypeErrors FieldTextUrn/FieldPubIdUrn construction inside Form::config::before; hook wrapper swallows it and the Identifiers form ships with zero fields (empty panel, no Save). Repro: enable urnpubidplugin + enablePublicationURN without saving the plugin settings form; fix: (bool)-cast getSetting('urnCheckNo') at plugins/pubIds/urn/URNPubIdPlugin.php:348." Spec workaround: seed `urnCheckNo: false` (what the settings form would have written) — row-6 coverage (gating + round-trip) survives intact.
- **Seeding gotcha:** publication titles exist ONLY when the spec carries a `publications[].metadata.title` — there is no default title in SubmissionBuilderProcessor. Every publication-panel Save PUTs the full entity, so a title-less seeded publication 400s ("title required") on its first save. Hand-rolled stage-1 specs in rows 5/6 carry an explicit publications block for this reason.
- **Citations surface reality:** the workflow nav entry is labelled "References" (`submission.citations`); the panel is the CitationManager (per-row citations table + `addCitations` import form), NOT the legacy `citationsRaw` textarea form. Reader rendering comes from `$publication->getData('citations')` (parsedCitations) in article_details.tpl; `citationsRaw` is only the legacy fallback.
- **Row 7 observed behavior:** clearing the License-panel fields round-trips as empty → publish-time defaults DO refill all three values (Laravel's ConvertEmptyStringsToNull + convertStringsToSchema turn cleared inputs into nulls, so the publish() `!getData(...)` guards fire). No app bug here.
