# Payments

- **Area:** 7. Plugins (key set)
- **Placement:** ojs
- **Budget:** 5 tests
- **Absorbs:** playwright/tests/subscription-config.spec.js (1 of its 5 tests — the Distribution → Payments settings test backs row 1; the other four are absorbed by subscriptions-management). Left in place this wave to avoid colliding with the subscriptions-management refit; if that plan relocates it, update row 1's path here.
- **Scenario needs:** journal scenario (`publishingMode`, `users`, `issues`, `contact` passthroughs — all existing; `contact` gives row 3 a tag-unique notify-mail recipient); `submission-published` fixture + per-publication `galleys` passthrough (row 3's restricted PDF galley is seeded, not added via POM — cheaper and identical state). Fees and payment settings are set through the UI (the forms are the surface under test). The completed-payment row records the fee through the product's own `PUT /api/v1/_submissions/{id}/payment` endpoint (the editor-side record-payment API; CSRF from `window.pkp.currentUser.csrfToken` of a loaded backend page) — product API, not a test seed. All on scratch journals; publicknowledge stays open access. NO live gateway calls ever — PayPal coverage is config-surface only (browser-side `page.route` guard on paypal.com; server egress separately firewalled by config.test.inc.php).
- **Implementation findings (wave 11):**
  - `purchaseArticleFeeEnabled` / `purchaseIssueFeeEnabled` are dead settings: declared in `PaymentTypesForm.php#36-44` but the template (`templates/payments/paymentTypesForm.tpl`) renders no fields for them and nothing consumes them — the real fee gates are `fee > 0` (`OJSPaymentManager.php#156-199`). Row 2 asserts the four fee fields only.
  - PaymentsGridHandler has NO row details action: `viewPayment` is an empty `// FIXME` stub (`controllers/grid/subscriptions/PaymentsGridHandler.php#139-142`) and no GridRow actions are registered. Row 4's planned "details action shows the record" half is dropped; the grid-listing half (payer/type/amount) fully covers the recorded payment.
  - Both paymethod plugin field groups use `showWhen: 'paymentsEnabled'` — enabling payments reveals Manual AND PayPal fields regardless of the selected plugin. Row 5 asserts the fields after enabling + selecting "Paypal Fee Payment" (display name has lowercase "pal": `plugins.paymethod.paypal.displayName` = "Paypal Fee Payment"; option value `PaypalPayment`).
  - The record-payment endpoint fulfills 'paid' via payMethodPluginName `'Waiver'` and 'waived' via `'ManualPayment'` — swapped labels (`api/v1/_submissions/BackendSubmissionsController.php#127,155`). No UI surface renders the plugin name, so coverage is unaffected; flagged for the app-changes ledger.
- **Round 2 / out of scope:**
  - Live PayPal checkout / IPN fulfillment — external gateway, round 2 (if ever; likely mock-server territory).
  - Self-serve subscription purchase checkout (purchaseIndividualSubscription.tpl flow through a gateway).
  - Editor-side APC waive/record UI: the REST endpoint exists (`_submissions/{id}/payment`) but no Vue dashboard surface currently consumes it — do not invent UI; revisit when the dashboard regains the payment column.
  - `restrictOnlyPdf` fee variant; issue-purchase fee flow (mirrors article purchase).
  - Payments-grid details action — revisit if `viewPayment` is ever implemented upstream.
