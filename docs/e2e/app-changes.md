## 3. Flakiness sources in the local/CI environment (not app code)

- **Server-side outbound HTTP can kill worker PHP servers** (2026-06-11 mass failure:
  190 ECONNREFUSED after 3 of 5 `php -S` processes died on hung ORCID-job Guzzle calls —
  §2 row 12). Hardened in `seed-test-config.js`: `[proxy]` now points at a dead local
  port (`127.0.0.1:9`) so all server-side egress fails in milliseconds, and
  `[schedule] task_runner = Off` so scheduled tasks run only when a serial spec invokes
  `lib/pkp/tools/scheduler.php` explicitly (charter principle 9 — a reminder task firing
  mid-parallel-run would also pollute Mailpit). `[queues] job_runner` stays On. The
  firewall also covers libxml/PHP-stream fetches (PKP wires `[proxy]` into both via
  `PKPContainer::settingProxyForStreamContext`); remotely-hosted DTDs the app validates
  against at request time (§2 row 13) are mirrored under
  `lib/pkp/playwright/fixtures/dtd/` and resolved offline via `XML_CATALOG_FILES`
  (exported by `start-php-server.js`). NOTE: re-seeding `config.test.inc.php` from the
  template resets `installed = Off` — always `npm run test:e2e:reset` (drops DB +
  config + auth together) rather than deleting the config file alone.
- **Stale gitignored build artifacts** (`styles/build.css`, `js/build.js`): an old build
  silently re-enables UI animations → 3 false failures in wave 1 (reduced-motion,
  task-templates, issues). Open follow-up in the inventory: bootstrap-time guard
  asserting the served CSS contains a `prefers-reduced-motion` block.
- **Rotating parallel-load flake tail**: ~1–2 random specs per local full run time out on
  dialogs/API calls and pass on retry (`retries: isCI ? 1 : 0`); suspected single-threaded
  PHP dev-server saturation. Pre-existing; open follow-up.
- **Test DBs installed before 2026-06-05 carry #12049→#12800 schema drift**
  (`edit_decisions.publication_id`); symptom: 500 on any decision. Fix: reset the DB
  (one-time local ALTERs were applied in wave 1; fresh installs are correct).
- **`playwright/.auth` storage-state files can tear under concurrent cross-agent logins**
  (one corruption observed wave 2); candidate hardening: atomic write in auth.js.
- **Parallel implementation agents must not share the default HTML reporter**: one wave-5
  agent's run died on `ENOENT: scandir test-results-wave5-…` when a sibling's output dir
  vanished mid-scan. Agents run their specs with `--reporter=list` (plus their private
  `--output` dir); only the orchestrator's full-suite runs use the default reporters.
- **Legacy grid header link actions can swallow a click right after a DataChangedEvent
  refresh** (~1 in 3 on the review-form elements grid's second "Create New Item");
  bounded retry pattern in `ReviewFormSettingsPage.openCreateElementForm`.
- **`pkpMail.inboxFor`/`latestTo` were unscoped until wave 9**: Mailpit's
  `/api/v1/messages?query=…` silently IGNORES the query (only `/api/v1/search` filters,
  verified live on 1.29.7), so `latestTo` returned the globally newest message of ANY
  recipient. Under parallel agents this caused real cross-talk: one agent extracted a
  sibling's invitation mail and followed its decline link, failing the sibling's test.
  Fixed in `mail.js` (inboxFor → /api/v1/search). Rule stands: prefer
  `pkpMail.find({to, contains: tag})` over inbox-wide reads.
- **`mailpit.spec.js` still runs `clearAll()` from the parallel project**: its
  `describe.configure({mode:'serial'})` only orders its own tests — sibling workers' (and
  parallel agents') in-flight mail is wiped whenever the spec runs. Its global-count leak
  check was reworked tag-scoped + control-bounded in wave 8 (it could never be stably
  green in parallel); the spec should move to the serial project in the
  test-infrastructure wave, where the stronger global-count form can return.
- **Deterministic tags repeat across runs on a long-lived DB**: tag helpers built only
  from workerIndex + test-title slug produce the same tag every run, so count-assertions
  on shared surfaces (issue TOC, archive) match leftovers from prior runs ("expected 1,
  received 3" — wave-7 article-landing, copied from the galleys spec's helper). Rule:
  tags that back COUNT assertions need a per-run random component (the
  `versioning-states.spec.js` shape).
- **Near-midnight TZ-skew on date-boundary seeds**: Node's clock (test runner, local TZ)
  and PHP/Postgres "now" can disagree across midnight — a subscription dated to start
  "today" (Node) read as starting "tomorrow" server-side and failed validity for ~2 h
  (subscription-access subscriber test, 2026-06-12 00:0x). Rule: any date a test writes
  that must already be in effect gets at least a day of slack; exact-boundary semantics
  belong to unit tests.
